## Design Context

### Users
Primary users are hiring evaluators reviewing a frontend take-home submission and, secondarily, a single productivity-focused user interacting with the demo. The interface needs to communicate capability quickly: architecture clarity, async state handling, and UI polish should all be obvious within the first minute.

### Brand Personality
Confident, sharp, productized. The interface should feel like a credible SaaS surface rather than a tutorial app or generic admin template. The emotional goal is trust through control, clarity, and visible engineering maturity.

### Aesthetic Direction
Bold productized light-mode dashboard. Use strong hierarchy, ink-tinted neutrals, indigo-driven accents, layered surfaces, and intentional emphasis without slipping into neon, glassmorphism, or dark-mode gimmicks. The app should feel reviewer-friendly and demo-ready, with a visible “show your work” quality.

### Design Principles
1. Make system state legible immediately: auth state, task status, filters, and async feedback should be obvious at a glance.
2. Show polish through restraint and hierarchy, not decorative excess.
3. Treat loading, errors, empty states, and reviewer scenarios as first-class product surfaces.
4. Keep the UI feeling shippable: strong spacing, consistent actions, and meaningful visual contrast.
5. Optimize for fast evaluation: the most important flows and architectural choices should be easy to discover.
